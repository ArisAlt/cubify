# Cubify audit — 2026-10-18

Design-system audit of the UI (`cubify.html` + `cubify.js`), a full test run, and the bugs found
(and fixed) while proving the firmware export and checking every board's pins.

## Test run

`npm test`: **132 tests, all pass** (was 98 at the start of the day). The harness now runs `cubify.js`
in strict mode, so an undeclared variable fails the suite. New suites: `firmware` (export + guide),
`boards-switch` (board data + switching), `ui` (tokens, dialogs, keyboard).

Real builds (generated `build.sh`, local QMK CLI 1.2 / vial-qmk, Python 3.14), all exit 0, 0 warnings:
AliceZero VIA, QMK and Vial on the RP2040-Plus; 2× Pro Micro split VIA; direct-wired 3×3 RP2040-Zero VIA;
4×4 Raspberry Pi Pico VIA.

## Bug report

| # | Bug | Effect | Status |
|---|-----|--------|--------|
| 1 | Vial export put `MATRIX_ROWS/COLS` and pins in `config.h` | vial-qmk's parser uses `ast.Num`, removed in Python 3.14: **Vial build failed** (plus an "overwriting" warning) | Fixed: one data-driven `keyboard.json` for VIA, QMK and Vial |
| 2 | `build.sh` copied new files over an older export | stale `info.json`/`config.h` overrode `keyboard.json` and broke the build | Fixed: removes them first |
| 3 | Vial `build.sh` used plain `make` | `arm-none-eabi-gcc: command not found` (only the `qmk` command puts QMK's compilers on PATH) | Fixed: adds `~/.local/share/qmk/bin` (or `$QMK_DISTRIB_DIR`) |
| 4 | Import KLE dialog used `var(--bg)`, never defined | dialog box **transparent**: the keyboard showed through the text | Fixed: `--panel-bg`; test fails on any undefined CSS variable |
| 5 | RP2040-Tiny default rows (GP0–6) and columns (GP10…GP1) overlapped | defaults unusable (the allocator fell back to the pool) | Fixed: Zero's defaults; pin list verified from Waveshare's pinout image |
| 6 | nice!nano / SuperMini used NFC pins (P0.09/P0.10) and the inner pad P1.02 early; P0.10 a default column | awkward/NFC pins wired before plain edge pins | Fixed: edge pins first, those last |
| 7 | Firmware MCU table fell back to RP2040 for any unknown board | a new board would silently get RP2040 firmware | Fixed: MCU/bootloader in `BOARD_META`; QMK uploads use their own `processor` |
| 8 | `numLogicalRows`/`numLogicalCols` assigned without a declaration | leaked onto `window`; would crash under strict mode | Fixed; harness now strict |
| 9 | No way to close dialogs from the keyboard; no dialog semantics | Escape did nothing; screen readers saw plain divs | Fixed: Escape closes, `role="dialog"`, `aria-modal`, labelled, focus moves in |
| 10 | Guide said "double-tap RESET" for every RP2040 | the Pico has no RESET button; double-tap only works once QMK is on it | Fixed: per-board buttons (Pico BOOTSEL; Tiny on its adapter) |
| 11 | `/etc/udev/rules.d/50-qmk.rules` on this PC contains `404: Not Found` | it masks the working `/usr/lib/udev/rules.d/50-qmk.rules`, so flashing a Pro Micro (avrdude) can fail | **Not changed (system file).** Fix: `sudo rm /etc/udev/rules.d/50-qmk.rules && sudo udevadm control --reload` |
| 12 | `periph` pin suggestions + encoder tooltip branch | dead code: `assignedEncoders` is never filled since the encoder UI was removed | Open: remove in a cleanup |

## Design system audit

**Components reviewed:** 10 buttons, 6 selects, 3 file/text inputs, 2 dialogs, step bar, key, tooltip,
banners · **Issues found:** 9 · **Score:** 62/100 → 74/100 after today's fixes

### Token coverage

| Category | Defined | Hardcoded values found |
|----------|---------|------------------------|
| Colors | 8 → 16 tokens (palette added: crust, surface, green, blue, peach, red, yellow, mauve) | 13 hex in HTML outside `:root` (mostly `#11111b` text on coloured buttons); drawing colours in `cubify.js` are data (wires, pads) and stay |
| Typography | 0 → 5-step scale (`--fs-xs`…`--fs-lg`) | 16 inline `font-size` values in HTML (12/13/14/18 px) |
| Radii | 0 → 3 (`--radius-sm/md/lg`) | 6 / 8 / 12 px used inline |
| Spacing | none | ad-hoc `gap`/`padding` in 60 inline `style=""` attributes |

### Naming consistency

| Issue | Where | Recommendation |
|-------|-------|----------------|
| Tokens used but never defined (`--peach`, `--blue`, `--red`, `--yellow`, `--bg`) | buttons, dialogs | Fixed: defined; `--bg` replaced |
| Mixed token names (`--bg-color`, `--key-bg`, `--panel-bg` vs palette names) | `:root` | Keep role tokens (`--panel-bg`) for surfaces, palette names for accents |
